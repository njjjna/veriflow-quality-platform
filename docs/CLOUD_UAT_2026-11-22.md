## 修复内容

1. **审批提交在发送请求前抛异常。** 原代码把CSS属性选择器传给 `getElementById`，得到空值后读取 `.checked`。改为从审批表单的命名控件读取五项确认。新增真实处理函数测试，确认请求内容、CSRF令牌及服务端拒绝提示。修复已通过非浏览器回归，浏览器复测待执行。
2. **API与浏览器用例相互污染。** 原Actions顺序运行两类测试却共用数据库；API先创建3条同源工单后，浏览器的“首次新建3条”断言将受到影响。新运行器为每个套件分别初始化全新数据库和附件目录，避免污染。
3. **测试依赖缺失。** 原有图片测试导入Pillow，但依赖清单未声明。增加 `requirements-test.txt` 并接入CI；全新虚拟环境测试由19通过1缺包修复为20通过。
4. **页面导航等待不充分。** 原脚本仅等待任意h1，可能在旧页标题上提前通过。改为等待目标页面的准确标题。浏览器验证待执行。

## 已准备的浏览器流程

`scripts/browser_uat.py` 将实际通过页面执行：

- 管理员登录；创建经理、测试、整改、验收、只读五种业务账号；首次改密与独立会话。
- 只读页面权限入口；初始上线门禁阻断。
- 12行异常样本、3条异常、异常工单去重。
- 创建并分配高风险工单；上传模拟截图；授权窗口预览；整改、拒绝自复测、独立复测关闭。
- 浏览器下载CSV并核对内容。
- 8项UAT由测试账号执行并由验收账号审核；异常数据继续阻止上线。
- 12行合格样本解除数据门禁；经理勾选五项模拟确认并提交；另一验收账号批准流程。
- 审计日志、390px总览溢出检查、退出与刷新、未捕获JavaScript异常检查。

这些是已编写的测试步骤，尚无本次浏览器执行结果。原生另存为弹窗、其他浏览器、完整可访问性及其他窄屏页面仍不在此自动化覆盖内。审批中的安全/回滚/备份资料均为模拟证据编号，不声称完成真实企业演练。

## 无需Docker的复现

```bash
python -m venv .venv
# 激活虚拟环境后：
pip install -r requirements.txt -r requirements-test.txt -r requirements-browser.txt
python -m playwright install --with-deps chromium
pytest -q
node --test tests/frontend_release.test.cjs
python scripts/run_isolated_uat.py --suite all
```

默认仅绑定127.0.0.1，不向公网提供应用。随机管理员口令只留在进程内存与子进程环境中，不写进报告。每次结果位于独立的 `test-artifacts/isolated/<run-id>/`，含 `run_summary.json`；浏览器套件运行后另有 `browser/browser_result.json`。只执行 `--suite api` 时，浏览器状态明确为 `not_run`。

本轮已实际执行API套件；未在受阻环境中调用浏览器套件。GitHub Actions将在独立GitHub运行器上按相同命令执行两套流程，运行结束上传报告、截图和诊断日志。需以Actions实际结论为准。
