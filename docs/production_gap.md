# VeriFlow — 工程上线验收与生产安全差距清单

**当前结论**：可作为本地/隔离演示环境、可复现作品集；**尚未达到企业公网生产发布准入条件**。本表用于控制宣传和安全边界。

## C. 本版本技术风险与限制

1. `Base.metadata.create_all` 仅用于全新数据库初始化，没有正式schema migration能力。
2. SQLite为本地开发/演示；跨多实例需PostgreSQL及连接池、迁移、备份和权限评审。
3. 账号创建产生随机临时密码并只显示给管理员一次，尚未实现到期邀请链接、邮件发信、强制限时和MFA。
4. 登录接口尚未添加持久化爆破限流，**不可直接作为公网生产登录服务**。
5. 默认 `COOKIE_SECURE=false` 为本地HTTP方便开发；公网TLS必须为true。CSP只覆盖基础资源白名单。
6. CSV的通用公式前缀规避不是对所有电子表格软件及保存/再打开流程的绝对防护，仍须针对目标Excel版本验证。
7. 异常工单指纹仅用于相同文件复现；未实现跨批次长期异常的语义去重、抑制期和趋势监控。
8. 已实现演示多角色组合和基础证据上传，但未实现附件版本控制、邮件/IM通知、逾期提醒、完整审批引擎、病毒扫描或合规保留策略。
9. 本版本的“上线审批”属于模拟业务治理演示，勾选安全/回滚/备份项不能证明这些活动真正完成；不能视为医疗系统安全合规或生产上线批准。

## D. 外部公开演示的推荐方式

部署**单独的演示环境**，只加载虚构机构数据，创建 `viewer` 只读账号。正式后台不可与演示环境共享数据库。不要把数据库密码、管理员账号、会话token或任何患者记录提交到GitHub。对外展示必须披露“模拟项目”“AI辅助开发”“未经过第三方安全审计”。
